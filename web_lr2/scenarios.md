# Сценарии и операции API

Достаточность контракта [`openapi.yaml`](openapi.yaml): для каждого шага сценария из
[`README.md` §6](../README.md#6-пользовательские-сценарии) указана операция (`operationId`),
которая его обслуживает. Шаги, выполняемые только в интерфейсе (открыть страницу, нажать кнопку
без обращения к серверу), в таблицу не включены.

## Сценарий 1. Регистрация (FR-01)

| Шаг | Действие | operationId | Ответы |
|---|---|---|---|
| 4 | «Зарегистрироваться»: проверка полей и уникальности | `createUser` (без токена) | 201; 400 — пустое поле или пароль не 8–128 символов (в `errors` указано, какое поле); 409 — логин или email заняты |

## Сценарий 2. Вход и выход (FR-02, FR-03)

| Шаг | Действие | operationId | Ответы |
|---|---|---|---|
| 4–5 | «Войти»: проверка учётных данных, создание сессии | `createSession` | 201 + токен; 401 — неверный логин или пароль (одно сообщение); 400 — пустые поля |
| после перезагрузки | Восстановление сессии (критерий: «переживает перезагрузку») | `getCurrentSession` | 200; 401 — токен истёк или сессия завершена |
| «Выход» | Завершение сессии | `deleteCurrentSession` | 204; 401 |

## Сценарий 5. Администрирование пользователей (FR-13…FR-16)

| Шаг | Действие | operationId | Ответы |
|---|---|---|---|
| 1 | Список пользователей и счётчики (всего — `total`, по роли — фильтр `role`) | `listUsers` | 200; 403 — не `admin` |
| 2 | «Добавить» | `createUser` (с токеном, `role`) | 201; 400 — в том числе пароль не 8–128 символов; 409 |
| 3 | Изменить все поля в модальном окне | `replaceUser` | 200; 400; 404; 409 |
| 3 | Сменить только роль или только пароль | `updateUser` (`PATCH`) | 200; 400 — в том числе пароль не 8–128 символов; 404; 409 |
| 4 | Удалить пользователя | `deleteUser` | 204; 404; 403 — не `admin` или удаляемый — `admin` (в том числе сам вызывающий) |

## Что изменено по итогам проверки

| Находка | Решение |
|---|---|
| Карта и список выбора загружают все аэропорты за один вызов, а `limit` позволял не больше 1000 | в `listAirports` максимум `limit` увеличен до 10000; добавлен поиск `q` |
| Критерий сценария 1: «показано, какое поле не заполнено» — в `Problem` нельзя указать поле | в `Problem` добавлено расширение `errors[{field, message}]` (RFC 9457 разрешает расширения) |
| Сценарий 4: «источник недоступен — остаются последние точки» — ответа об этом не было | в `listCurrentFlights` добавлен ответ `503` с `Retry-After` |

## Уточнение контракта 1.0.0 → 1.1.0

Найдено при проверке схем: пароль при создании и смене допускал 1 символ и не имел верхней границы.

| Что | Было | Стало |
|---|---|---|
| `UserCreate.password`, `UserPatch.password` | `minLength: 1` | `minLength: 8`, `maxLength: 128` |
| Ответ `400` (`ValidationError`) | один пример | два примера, добавлен `weakPassword` |
| Версия контракта | 1.0.0 | 1.1.0 |
| Затронутые шаги | — | сценарий 1 (шаг регистрации), сценарий 5 (шаги «Добавить» и `PATCH`) |

Разница файлов: [`versions/1.0.0-to-1.1.0.diff`](versions/1.0.0-to-1.1.0.diff). На вход (`createSession`) ограничение не распространяется.

## Операции, не используемые сценариями, и обоснование

| operationId | Почему оставлена |
|---|---|
| `getUser` | полный CRUD для `users` (требование задания): чтение одного ресурса; отдельного шага или экрана «карточка пользователя» в сценариях нет |
| `getAirport` | чтение одного ресурса по идентификатору — основа REST; нужно внешним интеграциям и SPA для открытия карточки аэропорта по ссылке |
| `listAircraft`, `getAircraft`, `listFlights`, `getFlight`, `listFlightPositions` | требование задания: доступ ко всем данным системы для внешних интеграций; в ER эти сущности есть, интерфейс их показывает только косвенно. **Доступ — `analyst` и `admin`:** гость по README видит только карту (маркеры судов и аэропорты), история точек рейса и справочник судов ему не нужны |
| `getReport` | на этот ресурс указывает заголовок `Location` из `createReport` (201), на нём же определён `DELETE`; без `GET` ссылка вела бы в никуда |
| `replaceUser` рядом с `updateUser` | `PUT` — форма редактирования целиком (все поля обязательны), `PATCH` — смена одного поля; семантика и идемпотентность разные |

Необоснованных методов не найдено: каждая операция либо нужна шагу сценария, либо требуется
заданием (полнота данных, CRUD, `Location`).

## Проверка CRUD и частичного обновления

| Требование | Где |
|---|---|
| Create | `createUser` — `POST /api/v1/users` |
| Read | `listUsers` — `GET /api/v1/users`; `getUser` — `GET /api/v1/users/{userId}` |
| Update (полное) | `replaceUser` — `PUT /api/v1/users/{userId}` |
| Update (частичное) | `updateUser` — `PATCH /api/v1/users/{userId}`, `application/merge-patch+json`, примеры: только роль, только пароль |
| Delete | `deleteUser` — `DELETE /api/v1/users/{userId}` |
