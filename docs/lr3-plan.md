# WebLab#3 — план реализации

Исходное состояние: черновая попытка этой же ЛР3 (10 из 23 операций), общий слой BusinessLogic/DataAccess,
Blazor Server обращается к сервисам и местами к репозиториям, ConsoleUI — к локальным сервисам.
Предыдущие незакоммиченные изменения OpenAPI и памяток сохраняются.

## Границы

- По решению автора остаётся один `/api/v1`; черновые контроллеры заменены полной реализацией.
- Единственный актуальный контракт — `web_lr2/openapi.yaml` для ЛР2 и ЛР3.
- Контроллеры преобразуют API DTO в доменные команды, вызывают сервисы и преобразуют результаты.
- Новое ядро — `ATAP.BusinessLogic/Domain`: модели и интерфейсы Repository без ASP.NET/Npgsql.
- `ATAP.DataAccess`: отдельные модели строк БД, SQL и явное преобразование в доменные модели.
- Старые модели/интерфейсы сохраняются как адаптеры совместимости для существующих UI и тестов.
- ConsoleUI переводится на HTTP-клиент API; Blazor сохраняется рабочим.
- Авторизация необходима для действующих ролей (бонус 1 логичен). Автор подтвердил простой
  POST login/logout с подписанным JWT, передаваемым как Bearer. Отдельной версии v2 нет.
- Асинхронный CSV: POST задания → 202 + Location/Retry-After → GET состояния → GET файла.
  Это polling; отдельные SSE/WebSocket/брокер для этой задачи не нужны.
  Сохранённый отчёт и задание выгрузки — разные сущности.

## Соответствие операций

| Группа | Было | Работа |
|---|---|---|
| Сессии | Черновые вход/выход | Простой POST login/logout, JWT с проверкой подписи и отзывом; пользователь возвращается при входе |
| Пользователи | Только старые локальные сервисы | Регистрация, список, чтение, PUT, PATCH, DELETE; права и конфликты |
| Aircraft | Нет API | Список/карточка, фильтры и пагинация в Repository |
| Flights | Только текущие позиции | Список/карточка/позиции; существование, фильтры и стабильный порядок |
| Airports | Черновые список/карточка | Полная реализация через домен и Repository |
| Congestion | Черновые JSON/CSV | Общий сервис, включительные даты, 31 день, сводка по всему набору |
| Reports | Черновые список/создание/чтение/удаление | Проверка владельца и повторная выгрузка по сохранённым параметрам |
| Exports | Нет | Фоновая генерация CSV с состоянием и проверкой владельца |
| TUI | Прямой доступ к БД | HTTP-клиент, прежние меню и обработка ошибок |
| Swagger | Черновая спецификация | Один актуальный YAML, схемы входа и Execute |

## Этапы и проверки

1. Модель и контракт: сначала изменения OpenAPI/ER/DDL/сценариев для новых ресурсов.
2. Первый вертикальный сценарий: HTTP аэропортов → сервис → Repository → PostgreSQL → DTO.
3. Остальные операции чтения, затем CRUD/авторизация/отчёты.
4. Асинхронные выгрузки: задания и результаты в БД, worker с корректным жизненным циклом.
5. TUI через API; при разумной стоимости — общий HTTP-клиент для Blazor (бонус 2).
6. Реальный стенд: успешные/ошибочные запросы, 404/403, PATCH, соответствие схемам.
7. Контролируемое локальное нарушение ответа: контрактный тест должен упасть,
   затем восстановление реализации и успешный повтор; без изменения ожидаемых результатов.
8. Статический анализ, unit/integration/E2E, проверка TUI/GUI/API, документация.
